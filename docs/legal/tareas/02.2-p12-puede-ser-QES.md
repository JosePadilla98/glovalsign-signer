# ¿En qué casos un .p12 (.pfx) puede usarse para una Firma Electrónica Cualificada (QES)?


Un archivo **PKCS#12 (.p12 / .pfx)** es solo un contenedor que almacena un certificado digital X.509 y, normalmente, su clave privada.  
Por sí mismo **no determina el nivel de firma (AES o QES)**.


La clave está en **qué tipo de certificado contiene** (si es cualificado o no) y **cómo y dónde se usa ese archivo**. El .p12 no es ni "avanzado" ni "cualificado" por sí mismo: todo depende del certificado X.509 que lleva dentro y del entorno de uso.

---

# ℹ️ ¿Qué es un OID?

Un **OID** (Object Identifier, Identificador de Objeto) es una secuencia numérica única que identifica de forma estándar un atributo, política o extensión en el mundo de la criptografía y los certificados digitales.

En los certificados X.509, los OID se usan para:
- Definir políticas de certificación (por ejemplo, si un certificado es cualificado o no)
- Identificar extensiones específicas (como el uso permitido del certificado)

Ejemplos relevantes para QES:

| OID | Significado |
|---|---|
| 0.4.0.194121.1.1 | `id-etsi-qct-esign` — Certificado cualificado para firma electrónica de persona física |
| 0.4.0.194121.1.2 | `id-etsi-qct-eseal` — Certificado cualificado para sello electrónico de empresa |
| 0.4.0.194121.1.3 | `id-etsi-qct-web` — Certificado cualificado para autenticación web |

Estos OID aparecen en las extensiones del certificado X.509 y son una de las pistas clave para saber si un certificado es "cualificado" según la normativa europea (eIDAS).

# 🧠 Idea clave

> Un .p12 **solo puede formar parte de una QES si el certificado X.509 que contiene es cualificado (tiene el OID adecuado y es de un QTSP en la Trusted List) y la firma se genera dentro de un QSCD (Qualified Signature Creation Device)**.

---


# 🔐 Requisitos para que una firma sea QES (eIDAS)

Para que una firma sea **Qualified Electronic Signature (QES)**, deben cumplirse TODOS estos puntos:

## 1. Certificado cualificado (X.509)
El certificado debe:

- Ser emitido por un **QTSP (Qualified Trust Service Provider)** reconocido
- Incluir el OID de política cualificada (por ejemplo, `id-etsi-qct-esign` para persona física, `id-etsi-qct-eseal` para sello de empresa)
- El QTSP y el servicio deben estar presentes y activos en la **EU Trusted List (TSL)**

> ⚠️ El OID es necesario pero NO suficiente: la validez cualificada depende también de la Trusted List y del estado del QTSP.

## 2. Uso de un QSCD

La firma debe generarse dentro de un **dispositivo seguro certificado (QSCD)**:

- DNIe / smartcard
- Token USB criptográfico certificado
- HSM certificado (local o cloud)
- Servicio de firma remota cualificada (cloud QSCD)

## 3. Clave privada protegida

La clave privada:
- ❌ No puede ser usada libremente desde el sistema operativo
- ❌ No debe poder copiarse o exportarse
- ✔️ Debe permanecer dentro del QSCD

---


# 📦 Entonces… ¿qué papel juega el .p12?

El .p12 es solo el contenedor. Lo relevante es:
- ¿El certificado X.509 que contiene es cualificado (tiene OID adecuado y es de QTSP en la Trusted List)?
- ¿Se usa en un entorno QSCD?

Un .p12 puede estar implicado en distintos escenarios:

---


## ❌ Caso 1: .p12 en el ordenador (uso normal)

- Certificado instalado en Windows/macOS/Linux
- Clave privada exportable
- Firma realizada por software local (Adobe, navegador, etc.)

👉 Resultado: **Firma Avanzada (AES)** (aunque el certificado sea cualificado, si la clave es exportable y no hay QSCD, solo puede ser AES)

---


## ⚠️ Caso 2: .p12 usado en entorno no exportable controlado

- El .p12 se importa en un sistema seguro
- El acceso a la clave privada está restringido
- El sistema actúa como QSCD (certificado o HSM)

👉 Resultado: **Puede ser QES si el entorno está certificado y el certificado es cualificado**

---


## ✔️ Caso 3: .p12 dentro de un QSCD certificado

- El certificado proviene de un QTSP
- El certificado es cualificado (tiene OID adecuado y QTSP en Trusted List)
- El sistema de firma (HSM / cloud / smartcard) está certificado como QSCD
- La clave privada nunca sale del entorno seguro

👉 Resultado: **Firma Cualificada (QES)**

---


# ⚠️ Punto crítico: OID y entorno

Un mismo archivo `.p12` **solo puede generar QES si el certificado X.509 que contiene es cualificado (tiene OID adecuado y es de QTSP en Trusted List)** y se usa en un QSCD certificado.

- Si el .p12 contiene un certificado NO cualificado (sin OID adecuado), nunca podrá generar QES, aunque se use en un QSCD.
- Si el .p12 contiene un certificado cualificado, puede generar QES solo si se usa en un QSCD.

👉 El archivo NO cambia, pero **debe contener un certificado cualificado**. El entorno de firma (QSCD) es imprescindible, pero no suficiente si el certificado no es cualificado.

---


# 🧩 Regla mental

> El .p12 es solo el “contenedor de credenciales”.  
> La QES depende de dos cosas:  
> 1. Que el certificado X.509 sea cualificado (OID adecuado y QTSP en Trusted List)  
> 2. Que la firma se realice en un QSCD

---


# 🔥 Conclusión

- Un `.p12` **no es cualificado ni avanzado por sí mismo**
- Puede estar presente en ambos escenarios
- Solo hay QES si:
  - el certificado es de un QTSP
  - el certificado es cualificado (tiene OID adecuado y QTSP en Trusted List)
  - y la firma se realiza dentro de un QSCD

> QES no es una propiedad del archivo ni del certificado aislado, sino del conjunto: certificado cualificado + QTSP en Trusted List + uso en QSCD.

---


# 📌 Resumen ultra corto

| Elemento | Importa para QES |
|----------|-----------------|
| .p12 | ❌ No |
| Certificado QTSP | ✔️ Sí |
| Certificado con OID cualificado | ✔️ Sí |
| QTSP en Trusted List | ✔️ Sí |
| QSCD | ✔️ Sí |
| Software en PC normal | ❌ No |

---

# 🧠 Validación real (flujo tipo DSS/Adobe)

Un validador serio (Adobe, DSS, etc.) sigue este flujo:

1. Extrae el certificado X.509 del contenedor (.p12, smartcard, etc.)
2. Lee los OIDs/políticas ETSI para saber el tipo (esign/eseal)
3. Consulta la EU Trusted List (TSL) para comprobar que el emisor es un QTSP y el servicio está marcado como “qualified”
4. Verifica si la firma se ha realizado en un QSCD (dispositivo seguro certificado)
5. Solo si todo esto se cumple, la firma se considera QES

> El OID es necesario pero no suficiente: la “QES-ness” es una propiedad del conjunto certificado + QTSP + Trusted List + QSCD, no solo del certificado ni del .p12.
